# CommonGround build audit — 12 October 2026

This is a source and integration review, not an independent security certification.

## Findings fixed

- **Expired workflow recovery:** all three unfinished review states now expire
  after the review deadline. An unreviewed expired case closes without inventing
  a verdict or action receipt. A crash between saving a workflow stage and signing
  can safely resume when no signed broadcast exists; ambiguous signed broadcasts
  stay pending rather than being replaced.
- **Evidence integrity and Unicode:** excerpts are bounded by UTF-8 bytes without
  splitting a code point. Exact messages are never silently truncated; over-limit
  messages, defenses, and appeals are rejected before submission. The v2 court
  recomputes the exact message hash, framed evidence digest, and case ID.
- **Address serialization:** v2 registration and website delegation now encode
  actual GenVM Address values, rather than ordinary hex strings. A real SDK codec
  regression covers the distinction.
- **Truthful Discord outcomes:** legacy finalization now preserves failed or
  partial Discord action outcomes instead of announcing that enforcement worked.
  V2 checks its worker lease immediately before starting an action; an interrupted
  action remains unknown and is not automatically repeated.
- **Public API isolation:** malformed request URLs return 400 without crashing
  the process. Public case lookup permits eight concurrent reads at most, keeping
  Discord readiness independent of a burst of case queries.
- **Reviewer/user path:** defense and appeal deadlines are announced and exposed
  by `/case status`. The website uses the hosted deployment address and explicitly
  labels historical contract appeal evidence. V2 controls remain gated by health.
- **SDK finality and legacy migration:** a real StudioNet receipt returns numeric
  `status: 7` and `statusName: FINALIZED`. The worker now recognizes that form.
  Legacy adjudications keep their original destination and method signature after
  rollout. Mixed execution receipts stay unresolved; a rollback is never treated
  as a successful action. Missing public cases are distinguished from RPC outages.

## Verification

`npm run verify` covers all four contract files, 25 direct contract tests,
9 core tests, 75 bot tests, TypeScript checking, and a production web build.
The workflow also starts an isolated PostgreSQL 16 service and runs
`npx tsx scripts/postgres-smoke.ts` before publishing an image. It checks case
deduplication, exclusive leases, state across a pool restart, finalized revisions,
completion, strike deduplication/retraction, and lease transfer. The generated
temporary schema is removed afterward; it never uses the production public schema.

Direct tests mock LLM results and companion views. They do not prove network
consensus or asynchronous delivery. StudioNet receipts, source readback, real
cross-contract decisions, and Discord smoke results are documented separately in
the deployment and live-verification records.

## Trust limits

Discord identities and captured content are attested by the bot. A matching hash
proves the snapshot did not change, not that Discord independently authenticated
it. Validator agreement applies to the decision enum; explanation prose is
non-authoritative. Executor receipts report bot outcomes and are not independent
Discord proof. Unsalted identifier hashes can be correlated. Public evidence is
permanent. No payments or private-message inspection are part of this product.
